# RUKOVODSTVO-zahodami.md — как Cowork ведёт Claude Code (этот репозиторий)

> Методология заходов для `matema-fest`. Механика арки — `ARKA.md §5`; вход Code — `CLAUDE.md`.

## Принцип
Claude Code стартует с ПУСТЫМ контекстом каждый сеанс: прошлого не помнит, сайт читает заново. Значит **всё, что должно сохраниться, живёт на диске** (файлы + файл-заход), а не в памяти. Cowork (сильная модель, полный контекст) думает и пишет заход; Code (быстрая модель, минимальный контекст) выполняет одну чёткую задачу и отдаёт отчёт. Цена ошибки — ПЕРЕДЕЛКА, поэтому дисциплина жёсткая.

## §1. Канал — один файл в папке арки
Обмен идёт через ОДИН файл `zhurnal/<арка>/kod_<тема>.md`: сверху — **заход** (пишет Cowork), снизу — `## ПЛАН` / `## ВОПРОСЫ` / `## ОТЧЁТ` (заполняет Code). Cowork берёт отчёт прямо из файла — ничего не переносить руками.

## §2. Стандартный текст владельцу → Code (полный путь + МОДЕЛЬ ВНУТРИ текста)
Владелец не вставляет весь заход — шлёт короткий текст с ПОЛНЫМ абсолютным путём файла ВНУТРИ и моделью первой строкой. Cowork СРАЗУ отдаёт этот текст готовым к пересылке:
```
Модель: <Sonnet 5 | Opus 4.8> — <одна фраза почему> (в Claude Code переключается /model).
Claude Code, твой заход — файл `<ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md`. Прочитай ТОЛЬКО его и то, что он называет; остальной сайт не изучай. Точка отката — git-коммиты по блокам. План, вопросы и финальный отчёт пиши в этот же файл (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай; пуш в main — только если заход просит.
```

## §3. Заход — дай Code всё, иначе соберёт не то
- Заход несёт ВСЁ: рабочая папка (репо), что прочитать ПОИМЁННО, что сделать, границы, как отчитаться. Скажи явно: «читай только названное, сайт не доразбирай».
- Дай существующие конвенции и имена авансом (дизайн-система сайта, где что лежит) → Code переиспользует, не плодит своё.
- Есть ошибка/лог/вывод PageSpeed — вкладывай RAW, не пересказ.
- **Критерий готовности — условие, которое может ПРОВАЛИТЬСЯ** (не «я закончу»): «страница на `matema-fest.ru/quiz/` открывается, 16 картинок на местах, `/weights` без файлов >500 КБ, вёрстка не сломана на 1440 и 390».
- **Точка отката — git** (коммиты по блокам). Деплой (пуш в `main`) — только по явному указанию; помни, что пуш идёт live за ~60–90 с.
- **ВСЕГДА требуй в `## ОТЧЁТ`: время прогона + потраченные токены** (в каждом заходе, не по запросу).
- **Преимущество Cowork:** ты сам видишь файлы. Трогает заход недавно менявшееся — сверься на живых файлах ПЕРЕД написанием.
- Лоссовый/двигающий заход (перенос, удаление, сжатие, правка путей) → встрой **верификатор** (§5).

## §4. Приёмка отчёта — суди по отчёту, но проверь ГЕЙТЫ
Пройди КАЖДЫЙ: критерий выполнен · числа сходятся · границы соблюдены (запрещённое не тронуто) · решения обоснованы · вопросы Code разобраны · верификатор/регрессия зелёные · **время+токены в отчёте** · нет тихого недобора (стоп до цели — заявлен громко). Дешёвый санити по живым файлам (`git status`, `tree`, `grep`) — не построчно. Дисциплинированное НЕ-действие (Code отказался от рискованного, вынес в отчёт) — это хорошо. Вердикт: принять ИЛИ вернуть на точечную дочистку. Приёмку — в `SESSIYA.md`. Вопрос Code без ответа → ответ в начало следующего захода.

## §5. Верификатор внутри захода (для потерь и перемещений)
Заход двигает/удаляет/сжимает → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходное → новое» полно (список потерь пуст); каждая ссылка резолвится (битых 0, программно). Ключ: **другой субагент, другой метод** (сверка с `git show`/бэкапом) — у автора правок слепые пятна.

## §6. Скелет захода (меняется только тело §3)
```
# Заход для Claude Code — <короткое имя>
> Читай ТОЛЬКО этот файл и названные в нём файлы. Сайт целиком НЕ изучай — заход самоценен.
> Вопросы и отчёт — в этот же файл (## ВОПРОСЫ / ## ОТЧЁТ). Метрика — КАЧЕСТВО.
> Модель: <Sonnet 5 | Opus 4.8> — <почему>.

## ПРОМПТ
### Цель — <что закрыть, 1–2 фразы>. <Если стоп до цели: получишь X, но НЕ Y.>
### Что прочитать (только это) — <точные файлы + зачем>
### 0. Первый ход — рабочая папка <репо>; откат = git-коммиты; ПЛАН в ## ПЛАН перед действиями.
### 1. Дисциплина — минимум без спекуляций; хирургия (каждая строка → к заданию); якорные замены abort при ≠1; оспорить ложную предпосылку. Субагенты: ≤5 параллельно, рейт-лимит=стоп+доклад; назвать сколько и на что.
### 2. Границы — <что НЕ трогать>.
### 3. Задача — <конкретно>. КРИТЕРИЙ ГОТОВНОСТИ: <проверяемое условие, которое может провалиться>.
### 4. Верификатор (если двигаем/теряем) — свежий субагент, другой метод, программно.
### 5. Отчёт → ## ОТЧЁТ: что сделал+зачем / как проверил / что НЕ трогал / вопросы / время+токены.

## ПЛАН — (заполняет Code)
## ВОПРОСЫ — (заполняет Code)
## ОТЧЁТ — (заполняет Code)
```

## §7. Тип захода и когда не усердствовать
Мутирующий (правит/двигает) → коммиты по блокам, проверка после каждого. Аналитический (только измеряет) → ничего не трогать, артефакт + предложения. Организационный (порядок папок/доков) → содержание не менять. Тривиальная правка (опечатка, одна строка) — без церемоний, не спрашивай трактовок.

## §8. Какую модель ставить (указывать В КАЖДОМ заходе, §2)
- **Дефолт — Sonnet 5** (исполнительский): заход полностью расписан (якорные замены, вставки дословным текстом, сборка/рендер, визуальная петля, `/weights`) — весь reasoning в заходе, глубина Opus ничего не покупает; дешевле, бережёт недельный кап.
- **Opus 4.8** — только когда план рождается ПО ХОДУ: сквозной рефактор, трудный дебаг, «разберись и почини» без готовых якорей.
- Метрика — стоимость за успешный РЕЗУЛЬТАТ, не за токен. Координацию гони на быстрой, сильную — на узкое ядро.
